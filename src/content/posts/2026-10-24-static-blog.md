**一句话结论**：个人博客不需要服务器。静态站更快、更安全、更便宜，代价是"即时编辑"和"原生交互"。

## 先说我踩过的三个坑

搭博客这件事，我前后折腾过三轮：

| 方案 | 为什么放弃 |
|---|---|
| WordPress + 云服务器 | 每月 ¥30 服务器 + 每周处理插件更新和垃圾评论，写了一篇就再没打开过 |
| 平台（公众号/知乎） | 不用运维，但样式不可控、文章搬不走、页面里塞满推荐流 |
| Notion 类工具直接发布 | 编辑体验好，但首屏要加载 3 秒以上，SEO 基本为零 |

三轮下来我发现，**问题从来不是"用什么工具写"，而是"这套东西值不值得我长期维护"**。任何需要我每月照看的东西，最后都会变成负担。

## 静态站是什么

把所有页面在**构建时**变成纯 HTML/CSS/JS 文件，然后扔到 CDN 上。

```
Markdown 文件 → 构建（几秒）→ dist/ 里的 20 个 HTML → 免费 CDN
```

没有数据库，没有后台进程，没有运行时。访问者拿到的就是一个 HTML 文件，和一张图片没区别。

## 三个数字

- **111 KB**：整站体积（不含图片）。一张手机照片的一半。
- **0 个**：需要维护的进程、插件、数据库。
- **¥0 / 月**：托管在 GitHub Pages / Vercel / Cloudflare Pages 的免费额度内。

## 代价一：改内容要重新构建

动态站点改一篇文章，点保存就生效。静态站要重新构建一次（我这里是 1.5 秒）+ 推送。

对个人博客来说这不构成问题——我一分钟就能重新发布一次；真正的成本是**心理上那一步**：你没法半夜想到一句话就改。我把它当成好事：写完就是写完，不会无限改下去。

## 代价二：原生交互做不了

登录、会员、评论、点赞——这些都需要后端。静态站的解法是接第三方：

- 评论 → Giscus（基于 GitHub Discussions，免费无广告）
- 统计 → Umami / Plausible（隐私友好的轻量统计）
- 表单 → 第三方服务或干脆放个邮箱

够用，但每一件都是"外部依赖"，需要时再加。

## 代价三：中文搜索天然很弱

静态站没有全文索引服务。我的做法是**构建时导出标题、摘要、标签**，浏览器端做简单的字符串过滤（下一篇细讲）。文章多了（几百篇以上）就得考虑换成 Pagefind 这类本地索引方案。

## 什么情况下别用静态站

- 你要做**内容付费 / 会员 / 登录**
- 有**多人协作编辑**需求（非技术写作者不会用 Git）
- 内容**每天更新几十篇**（构建会变慢）

## 具体怎么搭

技术栈：Astro 5 + Markdown + 原生 CSS，托管 GitHub Pages，推送自动构建。

选 Astro 而不是 Hugo/Hexo 的原因很实际：**内容是我的，样式也是我的**。主题不是装来的，是手写的一个 CSS 文件，想改颜色就是改几个变量；而文章是仓库里的 `.md`，随时能带走。
